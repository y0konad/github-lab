# Guía de Markdown Técnico

Buenas prácticas para estructurar documentación técnica legible y mantenible.

## Jerarquía de Títulos
- Usar un único `# H1` por documento como título maestro.
- Seguir jerarquía estricta sin saltarse niveles (`#` -> `##` -> `###`).

## Bloques de Código y Resaltado
- Especificar siempre el lenguaje del bloque (`typescript`, `bash`, etc.).
- Preferir ejemplos mínimos reproducibles antes que volcados masivos de código.

## Listas y Tablas
- Listas con sangría consistente de 2 espacios.
- Alinear tablas de manera uniforme para facilitar la lectura del diff en Git.
